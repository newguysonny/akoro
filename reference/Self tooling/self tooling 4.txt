‎The Async/Human-in-the-Loop UX You Described
‎
‎Your instinct is right — this needs async resumption, not blocking. Users shouldn't wait 10 minutes on a hung request.
‎
‎Two valid UX patterns
‎
‎A. Synchronous-ish (short wait)
‎
‎```
‎Agent: "I can't do this yet — requesting permission. 
‎        This may take a moment."
‎   [polls for ~30s]
‎Admin approves quickly → agent continues
‎   [if timeout] → "I'll notify you when approved."
‎```
‎
‎B. Fully async (recommended)
‎
‎```
‎Agent: "I've submitted a capability request (ID: req_123).
‎        I'll continue automatically once approved, or you 
‎        can check back."
‎   [request stored]
‎   [admin approves]
‎   [agent resumes via webhook/queue/notification]
‎```
‎
‎Pattern B is better because:
‎
‎· No artificial timeouts
‎· No blocking the conversation
‎· Admin can take hours/days
‎· User gets a real notification when done
‎
‎How resumption works
‎
‎You need a task queue / state store:
‎
‎```
‎request_capability()
‎  → writes to capability_requests table
‎  → creates a pending_agent_task (goal, context, user_id)
‎  → returns request_id to user
‎
‎admin approves
‎  → capability added to registry
‎  → triggers pending task
‎  → agent re-runs the goal with new capability available
‎  → notifies user
‎```
‎
‎This is a durable workflow — think Temporal, a job queue, or just a DB + worker.

‎The Things That Will Bite You
‎
‎Risk Why Mitigation
‎Request spam Agent requests a capability for every trivial gap Rate-limit per user/session; cache "already requested"
‎Social engineering User crafts prompts to get agent to request dangerous caps Admin sees context, not just op name; deny suspicious
‎Capability creep Admin approves everything → registry becomes unsafe Default-deny, review SLA, periodic audit
‎Agent misreports Agent says "requested" but request failed Confirm write to request store before telling user
‎Resumption loss Approval happens, pending task is lost Durable queue (not in-memory)
‎Permission scope Capability approved globally but user shouldn't have it Capabilities ≠ grants; check user-level auth too
‎Stale requests User's goal is gone by approval time Store goal + context; expire old requests
