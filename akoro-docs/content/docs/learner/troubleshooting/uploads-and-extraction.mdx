# Uploads and extraction

## It has been on "Extracting the text…" for ages

That card is the Reader telling the truth: your document is being
read so its text can be searched, cited, and taught from.

- **Text-layer PDFs** (born-digital documents) extract in seconds.
- **Scanned PDFs** are read page by page — a long scan can take
  several minutes before the first pages are usable. The card counts
  (*Page N of 27*): if the number is moving, it is working. Leave it
  running; extraction continues while you do other things, and the
  agent files the upload when it lands.

## The upload itself failed

- **Connection.** Uploads resume poorly on a dropped connection —
  retry on stable Wi-Fi.
- **The file.** A corrupted or password-protected PDF cannot be read;
  remove the protection or export a clean copy, then
  [upload again](/docs/learner/library/upload-a-record).
- **Size and shape.** If the same file fails twice at the same point,
  split it (a chapter at a time) — smaller documents extract faster
  and fail smaller.

## It extracted, but the text is wrong

Scanned handwriting and dense tables are the hard cases for any
reader. If answers cite the wrong lines, check the page in
[Original Content](/docs/learner/reader/reading-a-document) — what
the Reader extracted is what your agent can see. A cleaner scan (flat,
lit, straight) re-uploaded usually fixes what no setting can.

## My file is in the wrong folder

Not an upload problem — a filing one. The record's ⋯ menu and the
agent both re-file: see
[Folders and collections](/docs/learner/library/folders-and-collections),
or tell your agent *"move this to Biology Notes"*.
