# Agent Chat

Agent Chat is the conversational surface of the AI protégé, the learner's own
teaching agent. It answers study questions, explains topics and acts on the
learner's records through tools, all grounded in what the learner has taught it
and the data it is allowed to read. The same surface runs an instructor
assistant that drafts teaching activities from the teacher's own words.

> **Status: beta.** Some parts of Agent Chat are still rolling out.

## Who it is for

- **Learners** — the protégé tutors them, searches their library and records,
  plans study and starts sessions.
- **Instructors** — a teaching assistant that prepares activity drafts for
  human review, never assigning them on its own.

## Primary flow

1. The learner sends a message.
2. The conversation so far and the learner's own records are brought together
   to ground the turn.
3. The agent uses its tools to read the learner's data and carry out the
   request.
4. The reply is written in plain words from what the tools found.
5. The reply is checked before it is shown, then saved to the conversation.

Replies stream in as they are written. If a connection drops mid-turn, the
same turn can be retried and replays the same answer instead of re-running an
action.

## The protégé

The learner's agent is their protégé. Its name, level and session count come
from the learner's own agent record, and what the learner has taught it is all
it knows of a subject. When the learner asks to be taught something the protégé
has not been taught, the reply says so and offers the Teach me action. The
protégé reads the learner's active goals and running work so its advice stays
aligned with what the learner is trying to do.

## Acting through tools

The agent does more than talk: it can search the learner's library, read their
records, plan study and start sessions on their behalf.

- **The agent prepares, the human approves** — before the agent changes
  anything (creating, sending, challenging or publishing), the learner may be
  asked to confirm on a card. Nothing changes until they approve.
- **Answers come from the data** — when a question is about the learner's own
  records, the agent reads the data first instead of answering from memory.

## Grounding on the learner's records

Answers are grounded in the learner's own data, not the model's general
knowledge. The agent draws on the syllabus, past questions, what the protégé
has been taught, the learner's active goals and running work, their library
files and their saved memories. Instructors are grounded in their curriculum
and their pending activity drafts. If one of these sources is unavailable, the
chat carries on without it rather than failing.

## Session lifecycle

- **Saved conversations** — conversations are saved as they go, so a learner
  can leave and pick up where they left off.
- **Stop** — the learner can stop a running turn, which marks the reply as
  stopped and keeps whatever already streamed.
- **Modes and model picker** — three modes answer the learner: default, think
  (step-by-step reasoning) and research (a deeper pass with more references).
  The learner may pick a model, constrained to their plan's tier.
- **Continuations** — a tap on a confirmation card resumes the same flow
  headlessly so the agent applies the decision and narrates the outcome without
  a new learner message.

## Realtime

The answer streams live as it is written. The realtime side of the app — the
learner's agents, teaching sessions and switching between agents — always
runs as the signed-in learner, so no one can drive another learner's session.

## How replies are checked

A reply is not trusted as-is before it reaches the learner.

- **No internal clutter** — internal identifiers and machine markup are kept
  out of replies, so learners see names and links, never raw syntax.
- **Claims are checked** — a reply that promises an action that did not run,
  or reports work as done when it was not, is corrected before it stands.
- **Teach me is honoured** — a reply that promises the Teach me action without
  having run it gets the action it promised.
